# 笼中数独 - 开发维护手册

## 概述

本文档记录游戏开发过程中的重要修改、已知问题、架构设计和维护指南，方便后续开发者快速定位问题和进行迭代。

---

## 一、剧情系统（Story Engine）

### 1.1 立绘定位系统

**文件**：`story/story-engine.js`

**功能**：支持角色立绘在左侧或右侧显示，左侧立绘自动水平翻转。

**数据格式**：
```json
{
  "speaker": "沈墨",
  "text": "对话内容",
  "side": "left",    // "left" 或 "right"（默认 right）
  "emotion": "calm",  // 情绪/立绘变体
  "effect": 0         // 入场效果等级 0-3
}
```

**实现要点**：
- 通过 CSS 变量 `--flip-x` 控制水平翻转（左侧为 -1，右侧为 1）
- 所有入场/退场/待机动画都使用 `var(--flip-x)` 确保翻转正确
- 立绘定位：`left: 10px`（左）/ `right: 10px`（右）
- 背景对齐：`background-position: left bottom` / `right bottom`

---

### 1.2 背景切换系统

**文件**：`story/story-engine.js`、`pages/guide.js`、`game/renderer.js`

**已知问题 & 解决方案**：

**问题**：StoryEngine 的 `changeBg()` 调用后背景没有变化。

**根因**：
1. `renderer.js` 的 `_applyPageBg()` 使用 `Image.onload` 异步设置背景（带 `!important`）
2. `playLevelPreDialog()` 中的 `changeBg()` 在章节数据加载完成后同步调用
3. 但 renderer 的图片加载完成时间不确定，可能比 StoryEngine 晚，导致背景被覆盖

**解决方案**：
1. `changeBg()` 改用 `style.setProperty('background-image', url, 'important')` 确保优先级
2. `playLevelPreDialog()` 中的背景切换延迟 100ms 执行，确保在 renderer 图片加载完成之后

**代码位置**：
- `story/story-engine.js` - `changeBg()` 函数
- `pages/guide.js` - `playLevelPreDialog()` 函数开头的 setTimeout

**注意事项**：
- 任何需要在关卡开始时切换背景的地方，都要考虑 renderer 异步加载的问题
- 移动端和 PC 端使用不同的背景图（scenes 目录 vs backgrounds 目录）

### 1.3 剧情缓存机制

**缓存键名格式**：
- 关卡前置对话：`killersudoku_v2_level_dialog_pre_{levelId}_route{route}`
- 关卡通关对话：`killersudoku_v2_level_dialog_clear_{levelId}_route{route}`
- 章节开场：`killersudoku_v2_chapter_intro_{chapterId}_route{route}`
- 章节结局徽章：`killersudoku_v2_badge_{badgeId}`

**强制重播方式**：
1. URL 参数：`?story=1`（跳过所有剧情缓存检查）
2. 设置界面 → 数据管理 → 重置剧情缓存
3. 设置界面 → 数据管理 → 重置所有进度

**相关代码**：
- `pages/guide.js` - `playLevelPreDialog()` 中的缓存检查
- `pages/guide.js` - `markComplete()` 中的 `shouldPlayEnding` 计算
- `story/story-modal.js` - `StoryManager.shouldPlayEnding()`

---

### 1.4 章末结局触发逻辑

**触发条件**（必须同时满足）：
1. 当前关卡是章节最后一关
2. 徽章尚未获得（或 forcePlayStory 模式）

**双重校验**：
- `markComplete()` 中计算 `shouldPlayEnding`
- `playEndingThenOverlay()` 中再次校验 `realLastLevel`
- 防止任何情况下错误触发章末结局

**章末背景预切换**：
- 在播放 endingStory 之前，从 title 条目中提取 `bg` 字段
- 提前切换到章末场景背景，确保整个结局剧情在正确场景下播放

**代码位置**：
- `pages/guide.js` - `markComplete()` 函数
- `pages/guide.js` - `playEndingThenOverlay()` 函数

## 二、设置系统

### 2.1 数据管理功能

**位置**：设置界面 → ⚠️ 数据管理

**功能**：
1. **重置所有进度**（红色按钮）
   - 清除所有 `killersudoku_` 开头的 localStorage
   - 包含：关卡进度、剧情缓存、设置、徽章、专家系统数据等
   - 双重确认，清除后自动刷新页面

2. **重新播放剧情**（橙色按钮）
   - 仅清除剧情播放相关缓存
   - 包含：前置对话、通关对话、章节开场、结局徽章
   - 不影响关卡进度和设置

**代码位置**：
- `guide.html` - 设置弹窗 HTML 结构
- `pages/guide.js` - `initSettingsBindings()` 函数末尾

## 三、关卡数据结构

### 3.1 章节数据（chapters.json）

**章节级字段**：
- `chapterId` - 章节ID
- `title` - 章节标题
- `introStory` - 章节开场剧情
- `endingStory` - 章节结局剧情
- `badge` - 通关徽章
- `levels` - 关卡列表

**关卡级字段**：
- `levelId` - 关卡ID（百位数=章节，十位个位=关卡序号）
- `preDialog` - 关卡前置对话数组
- `clearDialog` - 关卡通关对话数组
- `boardData` - 棋盘数据
- `cages` - 笼子数据
- `features` - 功能开关

**对话条目格式**：
```json
{
  "speaker": "角色名",
  "text": "对话内容",
  "side": "left/right",      // 立绘位置（可选，默认 right）
  "emotion": "情绪名",       // 立绘情绪（可选）
  "effect": 0,               // 入场效果 0-3（可选）
  "voiceId": "VO_XXX_01",    // 配音ID（可选）
  "isNarration": true        // 是否为旁白（可选）
}
```

**特殊条目类型**：
- `type: "title"` - 标题卡，支持 `bg`、`subtitle`、`showBoard`、`bgm` 等字段

## 四、常见问题排查

### 4.1 剧情不播放

**排查步骤**：
1. 检查是否加了 `?story=1` 参数
2. 打开控制台，查看是否有 "📖 播放关卡前置对话" 日志
3. 检查 localStorage 中是否有对应的缓存键
4. 确认 `currentLevelData.preDialog` 是否存在且非空
5. 检查 StoryEngine 是否初始化成功

**常见原因**：
- 浏览器缓存了旧版 JS 文件 → 硬刷新或更新版本号
- 剧情已播放过，被缓存跳过 → 加 `?story=1` 或重置剧情缓存
- StoryEngine 加载失败 → 检查控制台报错

---

### 4.2 背景不切换

**排查步骤**：
1. 检查 `_LEVEL_SCENE_BG` 中是否有对应关卡的映射
2. 在控制台手动调用 `StoryEngine.changeBg(url)` 测试
3. 检查 `document.body.style.backgroundImage` 的值
4. 确认是否被 renderer 的 `!important` 样式覆盖

**常见原因**：
- renderer 异步加载图片后覆盖了 StoryEngine 的背景 → 延迟调用 changeBg
- 优先级不够 → 使用 `setProperty` + `!important`

---

### 4.3 章末结局不触发

**排查步骤**：
1. 确认当前关卡是否是章节最后一关
2. 检查 `shouldPlayEnding` 的值（在 markComplete 中打断点）
3. 检查徽章是否已获得（`Storage.hasBadge(badgeId)`）
4. 加 `?story=1` 测试是否能触发

**常见原因**：
- 徽章已获得，被缓存跳过 → 加 `?story=1` 或重置剧情缓存
- 不是章节最后一关 → 检查关卡数据
- `currentChapterData` 加载异常 → 检查章节数据加载

## 六、架构注意事项

### 6.1 避免"叠补丁"

**原则**：修复问题时先找根因，不要在外层加判断来掩盖问题。

**反例**：
- 背景不切换 → 加个 setInterval 反复设置
- 结局错误触发 → 加三层 if 判断

**正例**：
- 背景不切换 → 找到 renderer 异步覆盖的根因，统一用 setProperty + important
- 结局错误触发 → 梳理触发条件，确保单一数据源判断

### 6.2 缓存设计

- 所有缓存键统一前缀 `killersudoku_v2_`
- 重置功能按前缀批量清除，避免遗漏
- 强制播放模式（story=1）作为测试/调试手段

### 6.3 版本号管理

- 修改 JS/CSS 文件后，同步更新 HTML 中的 `?v=xx` 版本号
- 确保用户浏览器加载最新代码，避免缓存导致的"假bug"
