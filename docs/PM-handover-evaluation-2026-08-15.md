## 1. 项目概况

- **产品**：《笼局·三岔口》（英文名 Caged Cipher: Shanghai 1941），杀手数独 × 1941 上海谍战叙事的网页解谜游戏。
- **技术**：纯前端 HTML + Canvas 2D + ES Module + fetch，无框架、无构建；**必须本地 HTTP 服务器运行**（`start-server.bat`，入口 `game.html`，file:// 会白屏）。
- **规模**：7 章 63 关（101–709，每章 9 关、章末 Boss 战）；四语 i18n；专家系统 5 层；10+1 级技巧体系。
- **仓库**：GitHub `pskywoody/cage-master`（分支 cagemaster4），29 个提交（2026-08-09 首次全量入库 → 2026-08-14 推送），约 441MB。
- **内容管线**：63 关数据、四语剧本、i18n locale 资源、AI 实验体系（novice/expert/impatient LLM 模拟玩家）、关卡生成器（B3-FINAL 已冻结 100 关生产池）。

## 4. 质量与一致性风险（新 PM 需立刻盯住）

1. **文档漂移**：开发手册 hero 仍标"8 章 · 63 关"、§6.1 章节索引仍为旧 8 章结构（199/299/…/801-806）；MEMORY.md 关卡映射使用旧编号（门=401 等）；音频重估文档章节编号与现行结构不一致。→ 需一次"文档对账"。
2. **产品命名不一致**：中文《笼局·三岔口》vs 英文 Caged Cipher / 中文异名《笼中密信》在文档中混用（音频重估文档标题即《笼中密信》）。→ 需锁定品牌名（中/英/日/韩），并决定是否与《笼中密码》系列名统一。
3. **VO 上线后追加路径的隐性成本**：新剧本 VO 需**真实演员参考音**（IndexTTS 2.5 已装并验证，但项目无本地样本）；商用需 bilibili 授权；多语 VO 若做则 ×4 语。→ 建议立即启动"参考音采集 + 授权"并行，否则"上线后追加"会变成长期悬挂。
4. **技术债**：`game.html` 单文件 8,283 行（已做 CM 命名空间 + 拆 book-shell/freeplay 等，但 i18n/导航新增后又回涨）；eval 全局加载限制打包。→ 构建系统引入时一并治理。
5. **无 CI**：测试脚本虽多但无统一入口/看板，本次实测即发现陈旧测试未被发现。→ 最小 CI（GitHub Actions 跑 node --check + 核心测试）成本极低、收益高。
6. **四语 Boss 台词缺口（内容侧）**：EN/JA/KO 剧本缺 Boss 结算段（08-12 审计记录：EN 缺第 2 章 Boss 段、JA/KO 止于 709 无终章 Boss）——因终章并入第 7 章，需要产品确认是否补齐。
