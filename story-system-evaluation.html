已探索的完整系统架构

该项目构建了一个仿《逆转裁判》风格的七层剧情演出体系，从基础对话到Boss战演出形成完整链条。

第 1 层

StoryModal (story.js) — 基础对话系统

~570 行
  • 仿视觉小说对话框，支持角色头像 / 名称 / 打字机效果 / 点击继续
  • 章节标题卡（全屏文字展示）
  • BadgeAward 组件：徽章获得动画弹窗
  • StoryManager：剧情播放管理，判断是否播放开场 / 收尾剧情
  • 角色预设映射：7 个角色（守笼人 / 阿岩 / 设局人 / 残影 / 星辰梭 / 残局守护者 / 旁白）
  • 对话格式：{speaker, text} 自动映射到角色预设
第 2 层

StoryEngine v3 (scripts/story.js) — 逆转裁判演出引擎

~1568 行
  • 立绘砸入动画：从右侧砸入 + 弹性弹跳效果（portrait-slam 关键帧）
  • 情绪驱动演出：surprised/angry/sad/confident 推近拉远 + 抖动
  • "异议！"破局指示器：objection-pop 动画 + 震动 + 屏闪 + BGM 压低
  • 章节标题卡：金色大标题 + 字幕，缩放 + 字间距变化
  • 旁白模式：居中无框文字，斜体
  • 打字机速度变档：serene(80ms)/normal(40ms)/fast(15ms)/instant(0ms)/heavy(120ms)/thinking(60ms)
  • 情绪音效：surprised/angry/smirk/sad/think 分别触发不同音效
  • 立绘滤镜：角色情绪不同 → 不同的 CSS 滤镜
  • 立绘缩放：zoomPortrait('close'/'normal'/'far') 带过渡动画
  • 震动反馈：light/medium/strong/victory/slam/insight/objection/contradiction 分级
  • Boss 登场/击败/终章胜利 4 场顺序播放
  • BGM 压低 (ducking)：异议时 BGM 压到 20%，0.8 秒恢复
  • 配音系统：MP3 文件播放 + 音频解锁处理
  • 环境台词：sayAmbient 轻量对话，自动隐藏
  • 打字机音效：每 2 字触发一次 keyclick
  • 响应式适配：手机端立绘缩小、气泡位置调整
第 3 层

ComedySystem (utils/comedy.js) — 喜剧桥段系统

~300+ 行
  • 追踪状态：连续填错次数 / 总错误 / 正确数 / 提示次数 / 重置次数
  • 闲置检测计时器（逐级触发不同台词）
  • 守笼人毒舌 / 设局人打脸 / 阿岩吐槽
  • 气泡容器（最多同时 3 个）
  • 3 种角色对话方法：keeperSays / setterSays / ayanSays
  • 自动降级：StoryEngine → ComedySystem → 气泡
  • 连击检测 + 防刷屏（同一句话 3 秒不重复）
  • 角色立绘头像映射
第 4 层

DIALOGUES + SCENE_TRIGGERS (data/dialogues.js)

~330 行
  • 7 个角色定义含 voicePrefix 配音前缀、表情映射、Azure TTS 语音风格
  • 守笼人: 6 种 / 阿岩: 5 种 / 设局人: 7 种 / 残影: 4 种 / 星辰梭: 4 种 / 残局守护者: 3 种 / 秘术: 5 种
  • 共约 78+ 句台词（含无配音旁白 / 标题）
  • 每个台词有关联 scene 标签 + effect 等级 (0-4)
  • 共约 40+ 个场景标识：章节开场 (7)、Boss 登场 (7)、击败 (7)、破局、卡壳、终章真结局等
第 5 层

guide.js — 剧情集成

~300 行（剧情相关）
  • onPreDialogComplete / playLevelPreDialog 播放关卡前置对话
  • markComplete 播放通关剧情 + 徽章颁发
  • _onStoryCorrect / _onStoryWrong / _onStoryComplete 积分演出
  • 5 连击或 15 格正确 → 破局时刻 StoryEngine.breakthrough()
  • Boss 30 格正确 → 被逼入绝境场景
  • BOSS_CONFIGS + startBossBattle 启动 Boss 战
  • _initStoryPerformance 初始化 BGM / 配音 / 特效系统
第 6 层

Boss 战演出 (guide-battle.js)

~200+ 行
  • boss-dialogue-zone DOM 区域
  • _guideBossSay / _guideAyanSay 接口
  • 遭遇事件：远 / 中 / 近三档距离反馈
  • 抢格子闪光 + 烟雾 / 迷雾渲染
第 7 层

音频系统 (utils/audio.js)

~500+ 行
  • Web Audio API 程序化生成音效
  • 音效种类：click / correct / wrong / typewriter / portraitSlam / objection / bubblePop / thinking / emotion
  • BGM：暗黑 drone 低频嗡鸣 + 心跳脉冲
  • BGM 阶段切换：opening → breakthrough → finishing → victory
  • 混响效果 + 自动恢复音频

改进方向与路线图

基于深度分析，提出 10 项改进建议，按优先级分为 P0 (核心急需)、P1 (体验提升)、P2 (锦上添花) 三个等级。

P0 核心改进 急需处理 — 直接影响核心体验

1

增加台词量 P0

DIALOGUES 目前仅 78+ 句，需要扩充到 200+ 句。尤其是每一关的关卡内互动台词目前严重不足。建议为每章增加至少 10-15 句关卡进行中的吐槽/鼓励台词，以及关卡完成的庆祝/过渡对话。台词量直接从 78+ 提升 156%+ 至 200+，从根本上解决台词偏少的问题。

2

关卡内"实时剧情" P0

目前玩家解题过程中除破局/Boss 外基本无剧情互动。应在每个关键节点插入短对话： 首次填笼 → 守笼人惊讶反应；45 法则使用 → 阿岩教学台词；高级技巧使用 → 设局人残影回忆闪回。 建议利用现有的 ComedySystem 闲置检测机制扩展，在解题里程碑（填对 5/10/15 格）时触发轻量剧情。

3

Boss 战演出强化 P0

目前 Boss 战的对话仅为固定文本，需要根据玩家行为动态变化。建议： 将 guide-battle.js 中的 boss-dialogue-zone 升级为完整 StoryEngine 集成； 根据玩家连续正确/错误次数切换 Boss 的不同情绪状态（轻蔑→愤怒→震惊→绝望）； 增加 Boss"反击"机制——玩家连续填错时 Boss 释放"气场压制"特效。

P1 体验提升 显著改善 — 提升整体沉浸感

4

增加"待った！"和"指证！"机制 P1

在 Boss 战中增加更多逆转裁判标志性操作。"待った！"（Hold It!）可打断 Boss 台词并触发辩解动画；"指证！"（Take That!）在玩家填入正确数独值时触发"证据展示"演出。这两个机制可复用现有的 objection-pop 动画框架进行扩展。

5

立绘量扩充 P1

当前角色表情数量不均衡：设局人 7 种/守笼人 6 种较丰富，但星辰梭 4 种、残局守护者仅 3 种，严重欠缺。每个角色至少需要 5-6 种不同表情，特别是需要增加"轻蔑""震惊""悲伤""喜悦""困惑""专注"等基本情绪覆盖。这直接关系到 StoryEngine 情绪驱动演出的表现力。

6

结局演出扩展 P1

终章通关后增加各角色 结局后日谈。目前终章胜利仅有 4 场顺序播放（setter_defeat → setter_transfer → setter_farewell → true_ending），通关后缺乏角色归宿的交代。建议为守笼人、阿岩、星辰梭等主要角色各增加一段 30-60 秒的专属结局片段，参考逆转裁判系列的角色结局滚动展示方式。

7

配音文件生成 P1

目前的配音文件列表中只有少量 MP3，需要为所有 VO_*_ID 生成配音。可利用 Azure TTS（已在 dialogues.js 中配置语音风格）批量生成高质量配音文件。实现后可使用 StoryEngine 的配音系统（voiceManager）播放，配合 BGM ducking 效果达到专业级语音演出。

P2 锦上添花 长期优化 — 提升品质上限

8

多剧情线 P2

根据玩家表现（错误次数 / 解题速度 / 提示使用次数等）触发不同剧情分支。例如：连续错误 5 次 → 触发"守笼人焦虑"分支 vs. 零错误通关 → 触发"设局人赞赏"分支。可利用现有的 ComedySystem 状态追踪（连续填错次数 / 总错误 / 正确数 / 提示次数）实现条件分支。

9

闪回回忆系统 P2

在关键教学点插入设局人过去的闪回。例如：当玩家首次使用"45 法则"时，触发一段设局人年轻时学习数独的回忆片段。闪回可使用 StoryEngine 的 playScene 配合 sepia 色调滤镜 + 模糊效果实现。建议在 dialogues.js 中定义 FLASHBACK_* 场景标签配套实现。

10

章节间过渡动画 P2

当前章节过渡只有文本标题卡，可增加动态场景过渡。建议实现：章节结束时播放关卡场景"淡出 + 锁链碎裂"动画；章节开始时播放"笼子浮现 + 标题砸入"组合动画。可利用现有 portrait-slam 关键帧动画框架扩展为 scene-transition 关键帧。
